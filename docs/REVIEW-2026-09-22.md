## Assessment

The theme has a coherent, product-specific architecture and unusually useful source contracts. Shared resource cards, browse settings, metadata grouping, semantic tokens, translations, and production request guards are good foundations. A wholesale rewrite would offer little value.

The largest weaknesses are in failure paths and state transitions: the Sass compiler can report success after an error; release packaging is independent of the main CI gates; browse content depends on successful JavaScript initialization; and several interactive states are absent from the behavioral tests.

**14 prioritized findings: 0 P0, 4 P1, 10 P2.** P1 means address before the next release; P2 means a scoped correctness, accessibility, performance, or maintenance fix. No P3 cosmetic backlog is included.

Implementation integrity verdict: **pass for architectural coherence; release readiness needs the P1 fixes.** The automated Impeccable detector could not run because its engine was not installed and its cache directory was not writable. Findings below come from source inspection and explicit probes, not detector output.

## Findings

### 1. [P1] Sass compilation errors do not fail the build

**Location:** `gulpfile.js:99`; `package.json:8`.

The production compilation pipeline attaches `sass.logError` to the Sass error event. An isolated copy of this gulpfile compiling `.broken { color: ;` printed “Expected expression”, completed the `css` task, and returned exit code 0. The old compiled stylesheet remained present.

Consequently, the subsequent compiled-CSS lint can validate yesterday's valid CSS. The CI diff check also sees no change if compilation emitted nothing. This can allow a broken Sass source change to pass while silently shipping stale styling.

**Recommendation:** let compilation errors reject the build task. Keep watch-mode error recovery in a separate wrapper. Separate source lint from output verification so a missing/stale output does not prevent rebuilding it.

**Regression:** compile a deliberately malformed source in a temporary fixture; require a nonzero exit and prohibit success based on an old output artifact.

### 2. [P1] Release packaging is not gated by the full checks for the tagged commit

**Location:** `.github/workflows/release.yml:20`, `:36`, `:77`, `:144`, `:166`; `.github/workflows/ci.yml:10`.

The release workflow runs on tags or manual dispatch, validates metadata and archive structure, checks theme discovery, and uploads the zip. It never runs or requires the main build, unit tests, translation check, dependency audit, or PHP behavior matrix. The main CI workflow's push trigger is restricted to branches. The compatibility test checks discovery/configuration, not rendered PHP templates.

A tag naming a commit with stale CSS, a failing PHP template, or failing tests can therefore be packaged. An existing release is updated with `--clobber`. Repository-external tag protections could reduce this risk, but they were not inspected and the workflow itself does not enforce it.

**Recommendation:** reuse a validation workflow and make packaging depend on successful validation of the exact tagged SHA. Preserve the useful zip-content and packaged-theme discovery checks.

**Regression:** exercise release validation with an intentionally stale compiled file and a failing PHP behavior fixture; both must block packaging/upload.

### 3. [P1] Grid browsing has no usable failure fallback

**Location:** `asset/sass/components/resources/_resource-grid.scss:4`, `:32`; `asset/js/browse.js:42`, `:61`.

The default grid is transparent and every card is absolutely positioned. In an engine without native CSS masonry, disabling/losing the browse script leaves all results invisible. If only Masonry is missing, the fallback sets opacity to 1 but leaves positioning unchanged.

With the actual stylesheet, a two-card browser fixture had opacity 0 before enhancement. Loading `browse.js` without Masonry changed opacity to 1, but both cards occupied the same x/y coordinates. Waiting for the entire window `load` event also delays revealing results behind unrelated slow assets.

**Recommendation:** make an ordinary visible CSS grid the baseline. Apply Masonry-specific positioning only after successful initialization. Lay out when the component is ready and update when relevant images settle, rather than hiding all results until the whole page loads.

**Regression:** assert visible, non-overlapping results with JavaScript disabled, Masonry blocked, a failed thumbnail, and a delayed unrelated asset.

### 4. [P1] Value annotations cannot be opened with the keyboard

**Location:** `view/common/resource-values.phtml:132`; `asset/sass/components/annotation/_annotation.scss:43`; `asset/js/script.js:166`.

The trigger is a nonfocusable `div` containing a `span` with `role="img"`. The popover requires hover or focus within that wrapper, but its contents start at `visibility:hidden`, so neither the trigger nor its hidden links can receive keyboard focus. JavaScript handles mouseover/click positioning only. The loaded [Omeka 4.2.1 global script](https://github.com/omeka/omeka-s/blob/v4.2.1/application/asset/js/global.js) supplies no annotation or tabindex enhancement to compensate.

In a browser probe, Tab moved from the preceding button directly to the following button while the annotation stayed hidden. This prevents access to actual scholarly metadata, not just decorative help. It conflicts with [WCAG keyboard access](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html).

**Recommendation:** use a named native disclosure button with explicit expanded state and a controlled panel, or a suitable native disclosure. Support Enter/Space, Escape, and positioning on keyboard activation. Avoid placing interactive annotation content inside a button.

**Regression:** keyboard-only opening, reading/following annotation links, closing, and focus return at narrow and wide widths.

### 5. [P2] The locked development dependency fails the security gate

**Location:** `package.json:58`; `package-lock.json:3283`; `.github/workflows/ci.yml:48`.

`npm audit` reports sharp 0.35.3 affected by [GHSA-rgj7-g3m4-5g8c](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c), patched in 0.35.4. The advisory concerns libheif and processing untrusted images under affected conditions.

Here sharp is a development dependency used by the icon generator, with repository-owned inputs; it is not shipped as a server runtime in the theme archive. Do not describe this as demonstrated public-site remote code execution. The immediate confirmed effect is a failing mandatory CI audit gate.

**Recommendation:** update the lockfile to a patched compatible release, verify the icon generator, and rerun the dependency audit. Keep automated dependency update notifications enabled or add them if absent.

### 6. [P2] A private/excluded hierarchy item set can crash rendering

**Location:** `view/hierarchy/site/index/hierarchy.phtml:65`, `:75`, `:104`, `:107`.

When the item-set read fails, or a set is excluded from the site, the catch branch assigns `$itemSet = ''`. The later `!is_null($itemSet)` condition accepts that string. With `hierarchy_link_itemSet` enabled, the code calls `$itemSet->id()` on it.

This is a directly traceable fatal-error path, although PHP/Hierarchy runtime reproduction was unavailable locally.

**Recommendation:** represent unavailable sets consistently as `null`, guard object-dependent rendering, and explicitly handle the private label. Initialize recursive accumulators as arrays so a tree with no accessible sets also has a valid return value.

**Regression:** render hierarchies containing public, private, excluded, deleted, and no accessible item sets, with direct-link mode both enabled and disabled.

### 7. [P2] File/showcase blocks dereference missing media

**Location:** `view/common/block-layout/file.phtml:50`; `view/common/block-layout/item-showcase.phtml:21`.

Both templates allow `$attachment->media() ?: $item->primaryMedia()` to be null, correctly guard the thumbnail, then unconditionally call `$media->displayTitle()` when `showTitleOption` is `file_name`. A metadata-only item or an attachment whose media was removed can take down the page.

**Recommendation:** require media for the filename branch and define a deliberate title/omission fallback. Render captions with balanced wrappers even if the attachment's item is unavailable; showcase currently closes item-only wrappers from a separate caption branch.

**Regression:** render actual partials for no-media items, removed attachments, captions with/without items, and each title option. These tests should check rendered structure and absence of PHP warnings/errors.

### 8. [P2] Linked-resource work grows without a bound

**Location:** `view/omeka/site/index/linked-resources.phtml:70`; `view/common/linked-resources.phtml:58`, `:242`.

The endpoint sets `perPage` to the entire active subject-value count. All relationships are loaded, merged, sorted, and rendered with titles, classes, and thumbnails. A scroll-height limit bounds only the visual container; it does not bound server work, HTML size, image work, or the DOM. Client filtering traverses every loaded card.

Showing the full connection set is documented as an intentional product decision. The risk is therefore scaling that decision, not an accidental pagination typo. No production latency or memory threshold is claimed.

**Recommendation:** preserve full-set discovery through server-side search/facets and incremental result loading; alternatively define a measured limit and an explicit continuation path. Move connection aggregation to a testable helper. Benchmark high-degree authority records before choosing a threshold.

**Regression:** test realistic hub sizes and assert bounded initial payload/DOM and correct filtering across the complete result set.

### 9. [P2] Grid/list changes accumulate Masonry instances

**Location:** `asset/js/browse.js:47`, `:115`.

Every return to grid mode constructs `new Masonry(...)`. No instance is retained or destroyed on switching to list mode. The vendored library registers per-instance resize listeners and stores instances; a fresh constructor does not retire the earlier one.

A probe recorded four constructions after initialization plus three list/grid round trips. Old instances can continue measuring and writing layout on resize, multiplying work and competing for the same DOM. The list stylesheet's `!important` geometry overrides mask some symptoms.

**Recommendation:** own one instance per resource container, explicitly suspend/destroy it for list mode, and initialize/re-layout predictably for grid mode. Prevent queued pre-load initialization from creating stale instances after a mode change.

**Regression:** repeated toggles and resizes must retain at most one active layout engine per container.

### 10. [P2] Escape immediately reopens desktop submenus

**Location:** `asset/js/navigation.js:249`, `:260`.

Escape closes the submenu and then focuses its toggle. That focus generates `focusin` on the same item, whose handler unconditionally opens the submenu again. Starting from the parent link, a jsdom probe confirmed `.open` remains true after Escape.

**Recommendation:** coordinate focus restoration and disclosure state so restoring focus does not count as a fresh request to open. A single menu controller should own this transition.

**Regression:** Escape from the parent link and every submenu link closes the panel, restores focus, and leaves `aria-expanded=false`; reopening still works deliberately.

### 11. [P2] Custom brand contrast is overridden by the theme cascade

**Location:** `view/layout/layout.phtml:255`; `asset/sass/abstracts/variables/_colors.scss:43`, `:169`, `:251`.

PHP computes `--primary-contrast` and writes it to `:root`. The light/dark mixins then assign their own value on `body[data-theme]`, so descendants ignore the inherited PHP choice. In light mode with a valid white brand seed, the browser uses near-white text on the lightly darkened white fill; the repository's color utilities compute approximately **1.40:1** contrast.

The passing contrast checks cover the authored palette, not arbitrary admin settings. Simply moving the PHP value to body is insufficient: its calculation uses the raw seed, while buttons use mode-specific mixed fills and hover/active colors.

**Recommendation:** derive or validate accessible foreground/fill pairs for each mode and interaction state. Either constrain accepted brand colors or compute a complete safe palette. Extend contrast verification beyond the default seed.

**Regression:** white, black, yellow, and saturated custom seeds in both modes, including links, buttons, hover, active, and focus indicators.

### 12. [P2] Browse view state diverges between URL, DOM, and pagination forms

**Location:** `asset/js/browse.js:85`, `:88`; `view/common/pagination.phtml:25`.

The toggle pushes browser history and updates previous/next links, but never handles `popstate` or updates the page-jump form's hidden `view` field. A probe switching from `?view=grid` to list left the hidden form value at `grid`. Restoring a grid URL and dispatching `popstate` left the rendered layout as a list.

**Recommendation:** centralize an idempotent `applyView(view)` operation. Synchronize classes, controls, layout engine, links, and forms from that value; either restore it on history traversal or use replacement history if layout changes should not create navigation entries.

**Regression:** Back/Forward after several changes, page-number submission, next/previous navigation, and multiple browse-preview blocks on one page.

### 13. [P2] Dismissing installation leaves a dead visible control

**Location:** `asset/js/pwa-install.js:132`, `:138`.

The native prompt is single-use and `deferredPrompt` is cleared before it opens. If dismissed, the button stays visible although no prompt remains. A probe clicked twice after one event: the button remained visible and the browser prompt was invoked only once.

**Recommendation:** hide/disable the control once its prompt is consumed and reveal it only when a new install event becomes available. Handle rejection of `prompt()` as well as `userChoice`.

**Regression:** dismissal, acceptance, prompt rejection, repeated clicks, and receiving a new install event.

### 14. [P2] Array-shaped query input can produce a server error

**Location:** `view/omeka/site/index/linked-resources.phtml:39`.

`resource_property` is taken directly from the query and passed to `strpos`/`strstr`. Query parameters can be arrays, for example `?resource_property[]=items:`. A nonempty array passes the truthiness check and is invalid for the PHP string functions, producing a TypeError rather than falling back to the allowed resource type. This is a source-confirmed type path, not a local PHP execution result.

**Recommendation:** validate that the value is a string before parsing; validate the type and property-id shape together. Apply the same scalar-input discipline to `BrowseLayout::requestedView()` and the browse empty-state query text, which currently cast arbitrary query values to strings.

**Regression:** absent, empty, scalar, array, nested-array, unsupported-type, and malformed-property-id inputs.

## Refactoring opportunities

These are follow-up design improvements, separate from the 14 defects above.

1. **Make templates chiefly presentational.** Extract connection normalization/ranking from `common/linked-resources.phtml`, citation row/DOI construction from `record-apparatus.phtml`, and manifest construction from `layout.phtml` into helpers with explicit inputs/outputs. Keep escaping at the rendering boundary. The existing `ResourceGroups`, `BrowseLayout`, and shared resource card demonstrate the right direction.
2. **Replace the hierarchy renderer's mutable recursive closure with an indexed tree.** It repeatedly filters the whole grouping array, uses object-array membership searches, mutates captured traversal state, and reads each set during rendering. Build `byId`/`childrenByParent` maps, use an ID-based visited set, batch or memoize readable sets, and render the resulting tree. This makes cycle/missing-parent handling and escaping review tractable. Several raw label output branches also deserve a contextual escaping test; exploitability through the upstream module's inputs was not established here.
3. **Give navigation and browse one state owner each.** `script.js` closes drawers at a hardcoded 1200px breakpoint while `navigation.js` uses the actual overflow classification. Consolidate that rule and reuse shared readiness/debounce utilities. Build mobile section headers from just the relevant link rather than copying the parent's entire subtree with `innerHTML`; bind child propagation handlers once, not on every expansion.
4. **Make statistics fallback observable and resilient.** `CollectionStats` properly scopes public counts and caches by site, but broad catches silently hide integration failures. The API fallback can issue up to 18 item-count searches plus set discovery on a cold cache. Consider stale-on-error results, a refresh lock, and rate-limited diagnostics before adding more cache layers. Treat module source counts as an explicit adapter contract.
5. **Resolve optional-module policy explicitly.** Header assets and search widgets are guarded, but `DreSearchUrl` always constructs a module route and legacy routes always redirect to it. Either document DRESearch as an installation prerequisite or provide a core-search fallback when its route is absent. Test module-present, absent, and service-failure states separately.
6. **Reduce incidental duplication.** Consolidate repeated card data preparation, especially locale filtering and primary-media selection. Browse-preview currently accesses the first element of `media()` and computes thumbnails even when thumbnails are disabled; prefer `primaryMedia()` and defer work until needed. Move historical bug narratives out of long runtime comments where the current contract can be stated briefly. Share filesystem traversal and error-reporting code among custom checks without building a general lint framework.

## Testing improvements with the highest return

The existing suite is useful but uneven: ten of the 17 JavaScript tests exercise record/theme/navigation/PWA behavior; the remainder check fixtures and request/surface contracts. Browse, linked-resource behavior, annotation access, the token bridge, and Mirador timing have no direct local behavioral coverage. The navigation fixture has no submenu, so it cannot reveal finding 10. The single-citation test builds a tablist even though the PHP template omits one, illustrating fixture drift.

1. **Render real PHP partials with controlled representations.** Keep source contracts for registration, token names, and structural rules, but test output and edge cases for file/showcase blocks, hierarchy, record apparatus, locale filtering, and linked-resource input. Omeka theme discovery should remain one integration layer, not be treated as page-render verification.
2. **Add deterministic browser tests to pull-request CI.** Use local rendered fixtures with the actual CSS/scripts. Cover keyboard interaction, no-JS/network-failure behavior, multiple components, both themes, reduced motion, and narrow/wide viewports. Use automated accessibility checks plus explicit keyboard scenarios; ARIA attribute assertions alone do not establish accessibility.
3. **Test the failure states found here first.** Each numbered finding names a concrete regression case. Prioritize those over a blanket coverage percentage or source-pattern assertions that restate the implementation.
4. **Keep production smoke tests separate, but await feature readiness.** Several core tests check the error array immediately after an `h1` appears following `domcontentloaded`. A later asynchronous module error can escape the assertion. Await a meaningful completion state for each surface and decide which failed first-party requests should fail the test; currently failed requests are attached as diagnostics only. Preserve the read-only guard.
5. **Verify alternate renderers at the supported boundaries.** Add a small WebKit/Firefox sample for navigation, theme colors, native forms, and media layout. Neither a desktop Chromium viewport nor the CSS source target-size lint proves physical touch behavior or Safari compatibility.
6. **Add build/release contract tests.** Invalid Sass must fail; clean builds must reproduce tracked CSS; the exact tagged commit must pass required validation before uploading its archive. Continue testing the installed zip independently of the working tree.

## Practices worth retaining

- Public/site-scoped count queries and shared-locale cache separation.
- Semantic tokens with generated fallback tables, contrast calculations, and coordinated module aliases.
- A single resource-card partial and catch-all metadata grouping that preserves unknown properties.
- Attribute/content escaping in most theme-owned markup and safe JSON islands.
- PHP warnings/deprecations treated as test failures; CI covers PHP 8.1, 8.3, and 8.5.
- Unit-tested production request restrictions and separate scheduled integration checks.
- Actual release-zip structure checks and real Omeka theme discovery.
- Self-hosted fonts, reduced-motion alternatives, and guarded optional helper lookups.
